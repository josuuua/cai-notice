# CAI Notice 화면 설계서

## 1. 문서 기준

CAI Notice 1차 버전은 기존 동국대학교 공지 사이트처럼 공지를 카테고리별로 보여주는 서비스에 그치지 않고, 학생이 관심 있는 공지를 저장하고 폴더별로 관리하며 마감일을 일정으로 관리하는 **내 공지함 중심 MVP**로 설계한다.

1차 버전에서는 로그인/회원가입을 구현하지 않는다. 대신 브라우저에서 생성한 `guestId`를 기준으로 내 공지함, 폴더, ScheduleEvent 데이터를 저장하고 조회한다.

### 1차 필수 화면

1차 MVP에서 반드시 구현할 화면은 다음 8개다.

- 홈 화면
- 공지 목록 화면
- 공지 상세 화면
- 공지 저장 모달
- 내 공지함 화면
- 폴더 관리 모달
- 내 일정 화면
- 일정 등록/수정 모달

### 2차 이후 화면 또는 기능

다음 화면과 기능은 1차 범위에서 제외한다.

- 로그인 화면
- 회원가입 화면
- 마이페이지
- 월별 캘린더 UI
- 구글 캘린더 연동
- 푸시 알림
- AI 요약
- AI 마감일 자동 추출
- 공유 폴더
- 협업 기능
- 관리자 화면
- 첨부파일 분석
- PDF/HWP 요약
- 이미지/표 완전 재현

## 2. 공통 정책

### 2.1 guestId 생성/확인 흐름

1차 버전의 사용자는 로그인 사용자가 아니라 익명 guest 사용자다.

```text
사용자 최초 접속
-> 프론트엔드가 localStorage에서 cai_notice_guest_id 확인
-> 값이 없으면 crypto.randomUUID() 등으로 guestId 생성
-> localStorage에 cai_notice_guest_id 저장
-> /api/me 계열 API 요청 시 X-Guest-Id 헤더로 guestId 전달
-> 백엔드는 guestId로 GuestUser를 조회하거나 생성
-> GuestUser에 기본 폴더가 없으면 자동 생성
```

프론트엔드 저장 키는 다음으로 통일한다.

```text
localStorage key: cai_notice_guest_id
API header: X-Guest-Id
```

브라우저 localStorage를 삭제하거나 다른 브라우저/기기에서 접속하면 기존 `guestId`를 알 수 없으므로 이전에 저장한 내 공지함, 폴더, ScheduleEvent 데이터에 접근할 수 없다. 이 한계는 1차 버전에서 허용한다.

나중에 로그인 기능을 추가할 수 있도록 백엔드는 `GuestUser` 또는 확장 가능한 `User` 구조를 고려한다.

### 2.2 공지 본문 제공 방식

1차 버전에서도 사용자는 대부분의 공지 내용을 CAI Notice 안에서 확인할 수 있어야 한다.

- `Notice`에는 `content` 필드를 유지한다.
- 공지 목록 화면에서는 제목, 카테고리, 작성일, 출처, 본문 일부 미리보기를 보여준다.
- 공지 카드를 클릭하면 공지 상세 화면으로 이동한다.
- 공지 상세 화면에서는 공지 본문 전체를 보여준다.
- 내 공지함에서 저장한 공지를 클릭해도 같은 공지 상세 화면으로 이동한다.
- 원본 공지 링크는 메인 확인 수단이 아니라 출처 확인 및 최신 내용 검증용 보조 링크다.
- 원본 링크 버튼 이름은 모든 화면에서 `원본 공지 확인`으로 통일한다.

### 2.3 공통 내비게이션

1차 화면에서 반복적으로 사용하는 이동 버튼 이름은 다음으로 통일한다.

- `내 공지함`
- `내 일정`
- `원본 공지 확인`
- `저장`
- `일정 등록`
- `뒤로가기`

## 3. 1차 전체 사용자 흐름

```text
홈 화면
-> guestId 생성 또는 확인
-> 학과 선택
-> 시작하기
-> 공지 목록 화면
-> 전체 공지 또는 내 학과 공지 확인
-> 공지 상세 화면에서 본문 확인
-> 공지 저장 모달에서 폴더, 메모, 일정 선택 입력
-> 내 공지함 화면에서 저장 공지 관리
-> 내 일정 화면에서 등록한 ScheduleEvent 확인
```

## 4. 홈 화면

### 목적

홈 화면은 사용자가 CAI Notice의 목적을 이해하고, 내 학과 공지 조회에 사용할 학과를 선택한 뒤 공지 목록으로 진입하는 화면이다.

### 주요 요소

- 서비스 이름: CAI Notice
- 서비스 소개 문구
- 학과 선택
- 시작하기 버튼
- guestId 생성/확인 처리

### 동작

- 화면 진입 시 프론트엔드는 `localStorage.cai_notice_guest_id`를 확인한다.
- 값이 없으면 `guestId`를 생성해 localStorage에 저장한다.
- 값이 있으면 기존 `guestId`를 계속 사용한다.
- 사용자가 선택한 학과는 내 학과 공지 탭 필터에 사용한다.
- 학과 선택 값은 프론트엔드에서 `localStorage.cai_notice_department`로 저장할 수 있다.

### 화면 예시

```text
CAI Notice

동국대학교 공지를 저장하고,
폴더와 마감 일정으로 관리하세요.

학과 선택
[ 컴퓨터공학과 v ]

[ 시작하기 ]
```

## 5. 공지 목록 화면

### 목적

공지 목록 화면은 사용자가 전체 공지 또는 내 학과 공지를 검색/필터링하고, 필요한 공지를 저장하거나 상세 화면으로 이동하는 화면이다.

### 주요 요소

- 검색창
- 전체 공지 / 내 학과 공지 탭
- 카테고리 필터
- 공지 카드 목록
- 공지 제목
- 본문 일부 미리보기
- 저장 버튼
- 자세히 보기 또는 카드 클릭
- 원본 공지 확인 버튼
- 내 공지함 이동
- 내 일정 이동
- 검색 결과 없음 상태

### 탭

- `전체 공지`: 수집된 전체 공지를 보여준다.
- `내 학과 공지`: 사용자가 홈 화면에서 선택한 학과와 관련된 공지를 보여준다. 학과가 `전체`인 공지도 함께 포함할 수 있다.

### 카테고리 필터

1차 버전의 기본 카테고리는 다음을 기준으로 한다.

- 전체
- 학사
- 장학
- 학과
- 일반
- 비교과

### 공지 카드 구성

공지 카드에는 다음 정보를 표시한다.

- 카테고리
- 공지 제목
- 본문 일부 미리보기
- 작성일
- 학과
- 출처
- 저장 상태
- 저장 버튼
- 원본 공지 확인 버튼

카드 영역 또는 `자세히 보기`를 클릭하면 공지 상세 화면으로 이동한다.

### 화면 예시

```text
CAI Notice

[ 내 공지함 ] [ 내 일정 ]

[ 공지 검색하기...                   ]

[ 전체 공지 ] [ 내 학과 공지 ]

카테고리
[ 전체 ] [ 학사 ] [ 장학 ] [ 학과 ] [ 일반 ] [ 비교과 ]

--------------------------------
[학사]
2026학년도 2학기 수강신청 안내

수강신청 기간, 장바구니 일정, 정정 기간을 안내합니다...

작성일: 2026-06-11
학과: 전체
출처: 동국대학교 학사공지

[ 저장 ] [ 원본 공지 확인 ]
--------------------------------

--------------------------------
[학과]
컴퓨터공학과 졸업요건 안내

졸업요건, 이수 기준, 제출 서류를 확인하세요...

작성일: 2026-06-12
학과: 컴퓨터공학과
출처: 컴퓨터공학과 홈페이지

[ 저장 ] [ 원본 공지 확인 ]
--------------------------------
```

### 검색 결과 없음 상태

```text
검색 결과가 없습니다.
다른 키워드로 다시 검색해보세요.
```

## 6. 공지 상세 화면

### 목적

공지 상세 화면은 선택한 공지의 본문 전체를 CAI Notice 내부에서 확인하고, 저장 또는 일정 등록으로 이어지는 화면이다.

### 주요 요소

- 공지 제목
- 카테고리
- 학과
- 작성일
- 출처
- 공지 본문 전체
- 저장 버튼
- 일정 등록 버튼
- 원본 공지 확인 버튼
- 뒤로가기 버튼
- 저장된 공지인 경우 `이미 저장된 공지입니다` 상태 표시

### 동작

- 공지 목록에서 공지 카드 또는 자세히 보기를 클릭하면 이동한다.
- 내 공지함에서 저장 공지를 클릭해도 같은 공지 상세 화면으로 이동한다.
- `저장`을 클릭하면 공지 저장 모달을 연다.
- 이미 저장된 공지는 저장 버튼 대신 `이미 저장된 공지입니다` 상태를 보여준다.
- `일정 등록`을 클릭하면 해당 공지와 연결된 일정 등록/수정 모달을 연다.
- `원본 공지 확인`은 원본 사이트의 최신 내용을 확인하기 위한 보조 링크다.

### 화면 예시

```text
[ 뒤로가기 ]

2026학년도 2학기 수강신청 안내

카테고리: 학사
학과: 전체
작성일: 2026-06-11
출처: 동국대학교 학사공지

수강신청 기간 안내

1. 장바구니 기간
2026-07-20 ~ 2026-07-22

2. 본 수강신청 기간
2026-08-03 ~ 2026-08-07

3. 유의사항
...

[ 저장 ] [ 일정 등록 ] [ 원본 공지 확인 ]
```

저장된 공지 상태 예시:

```text
[ 뒤로가기 ]

2026학년도 2학기 수강신청 안내

이미 저장된 공지입니다.

[ 일정 등록 ] [ 원본 공지 확인 ]
```

## 7. 공지 저장 모달

### 목적

공지 저장 모달은 사용자가 관심 있는 공지를 내 공지함에 저장하고, 선택적으로 ScheduleEvent를 함께 등록하는 모달이다.

### 주요 요소

- 공지 제목
- 폴더 선택
- 새 폴더 생성 이동 또는 간단 생성
- 메모 입력
- 일정 등록 여부
- 시작일 입력
- 종료일 입력
- 저장하기 버튼

### 저장 흐름

```text
1. 공지 목록 또는 공지 상세 화면에서 [저장] 클릭
2. 공지 저장 모달 열림
3. 저장할 폴더 선택
4. 메모 입력 선택
5. 일정 등록 여부 선택
6. 일정 등록을 선택한 경우 시작일/종료일 입력
7. [저장하기] 클릭
8. 저장 공지는 내 공지함에 추가됨
9. 일정 날짜를 입력한 경우 내 일정에도 ScheduleEvent가 함께 등록됨
```

일정 등록은 필수가 아니라 선택이다.

### 폴더 기본 동작

- guest 사용자마다 기본 폴더가 자동으로 존재한다.
- 사용자가 폴더를 선택하지 않으면 기본 폴더에 저장한다.
- 같은 공지를 중복 저장하지 않는다.
- 이미 저장된 공지를 다시 저장하려고 하면 `이미 저장된 공지입니다` 상태를 보여준다.

### 화면 예시

```text
공지 저장

2026학년도 2학기 수강신청 안내

저장할 폴더
[ 기본 폴더 v ] [ 새 폴더 만들기 ]

메모
[ 장바구니 기간과 정정 기간 확인 필요          ]

일정 등록
[ ] 이 공지의 마감일 또는 신청 기간을 내 일정에 등록

시작일
[ 2026-08-03 ]

종료일
[ 2026-08-07 ]

[ 저장하기 ]
```

## 8. 내 공지함 화면

### 목적

내 공지함 화면은 사용자가 저장한 공지를 폴더별로 다시 확인하고 관리하는 CAI Notice의 핵심 화면이다.

### 주요 요소

- 폴더 목록
- 전체 저장 공지
- 기본 폴더
- 사용자 생성 폴더
- 저장 공지 카드
- 저장 공지 클릭 시 공지 상세 화면 이동
- 폴더 이동
- 메모 수정
- 저장 취소
- 원본 공지 확인
- 빈 상태 화면

### 폴더 목록

- `전체 저장 공지`: 모든 저장 공지를 보여주는 가상 목록이다.
- `기본 폴더`: guest 사용자마다 자동 생성되는 폴더다.
- 사용자 생성 폴더: 사용자가 직접 만든 폴더다.

### 저장 공지 카드 구성

- 카테고리
- 공지 제목
- 본문 일부 미리보기
- 작성일
- 출처
- 현재 폴더
- 메모
- 폴더 이동 버튼
- 메모 수정 버튼
- 저장 취소 버튼
- 원본 공지 확인 버튼

저장 공지 카드를 클릭하면 공지 상세 화면으로 이동해 본문 전체를 확인한다.

### 화면 예시

```text
내 공지함

[ 공지 목록 ] [ 내 일정 ] [ 폴더 관리 ]

폴더
[ 전체 저장 공지 ]
[ 기본 폴더 ]
[ 장학 공지 ]
[ 졸업 요건 ]

--------------------------------
[학사]
2026학년도 2학기 수강신청 안내

수강신청 기간, 장바구니 일정, 정정 기간을 안내합니다...

작성일: 2026-06-11
출처: 동국대학교 학사공지
폴더: 기본 폴더
메모: 장바구니 기간 확인

[ 폴더 이동 ] [ 메모 수정 ] [ 저장 취소 ] [ 원본 공지 확인 ]
--------------------------------
```

### 빈 상태 화면

```text
아직 저장한 공지가 없습니다.
관심 있는 공지를 저장하면 이곳에서 다시 확인할 수 있어요.

[ 공지 보러 가기 ]
```

## 9. 폴더 관리 모달

### 목적

폴더 관리 모달은 사용자가 내 공지함의 폴더를 생성, 수정, 삭제하는 모달이다.

### 주요 요소

- 폴더 생성
- 폴더 이름 수정
- 폴더 삭제
- 기본 폴더 삭제 불가 상태
- 폴더 삭제 시 저장 공지를 기본 폴더로 이동한다는 안내

### 폴더 정책

- guest 사용자마다 기본 폴더가 자동으로 존재한다.
- 기본 폴더는 삭제할 수 없다.
- 폴더 생성, 수정, 삭제가 가능하다.
- 폴더 삭제 시 해당 폴더에 있던 저장 공지는 기본 폴더로 이동한다.
- 폴더 삭제는 공지 자체나 저장 공지를 삭제하지 않는다.

### 화면 예시

```text
폴더 관리
```

## 10. 내 일정 화면

### 목적

내 일정 화면은 사용자가 직접 등록한 ScheduleEvent를 날짜별 목록으로 확인하고 수정/삭제하는 화면이다.

1차 버전에서는 복잡한 월별 캘린더 UI를 만들지 않는다. 실제 구현 범위는 `내 일정` 또는 `마감 일정 목록` 형태이며, 날짜별로 등록된 일정을 리스트로 보여준다.

### 2차 이후로 미루는 일정 기능

- 월별 캘린더 UI
- 구글 캘린더 연동
- 알림 기능
- AI 마감일 자동 추출

### 주요 요소

- 날짜별 일정 목록
- 연결된 공지 제목
- 연결된 공지 클릭 시 공지 상세 화면 이동
- 메모
- 수정/삭제
- 원본 공지 확인
- 빈 상태 화면

### 화면 예시

```text
내 일정

[ 공지 목록 ] [ 내 공지함 ]

2026-08-03 ~ 2026-08-07
--------------------------------
수강신청 기간

연결 공지:
2026학년도 2학기 수강신청 안내

메모:
장바구니와 정정 기간도 함께 확인

[ 공지 보기 ] [ 수정 ] [ 삭제 ] [ 원본 공지 확인 ]
--------------------------------

2026-09-10
--------------------------------
장학금 신청 마감

연결 공지:
2026학년도 2학기 교내장학금 신청 안내

메모:
서류 제출 여부 확인

[ 공지 보기 ] [ 수정 ] [ 삭제 ] [ 원본 공지 확인 ]
--------------------------------
```

### 빈 상태 화면

```text
등록된 일정이 없습니다.
마감일이 있는 공지를 일정으로 등록해보세요.
```

## 11. 일정 등록/수정 모달

### 목적

일정 등록/수정 모달은 공지와 연결된 ScheduleEvent를 사용자가 직접 등록하거나 수정하는 모달이다.

### 주요 요소

- 일정 제목
- 시작일
- 종료일
- 연결 공지
- 메모
- 저장 버튼

### 동작

- 공지 상세 화면의 `일정 등록` 버튼에서 열 수 있다.
- 공지 저장 모달에서 일정 등록을 선택한 경우에도 같은 입력 구조를 사용한다.
- 내 일정 화면에서 기존 ScheduleEvent의 `수정`을 클릭하면 수정 모드로 열린다.
- 시작일과 종료일이 같은 경우 단일 마감일로 표시한다.
- 시작일과 종료일이 다른 경우 기간 일정으로 표시한다.

### 화면 예시

```text
일정 등록

연결 공지
2026학년도 2학기 수강신청 안내

일정 제목
[ 수강신청 기간                    ]

시작일
[ 2026-08-03 ]

종료일
[ 2026-08-07 ]

메모
[ 신청 시간과 정정 기간 확인        ]

[ 저장 ]
```

수정 모드 예시:

```text
일정 수정

연결 공지
2026학년도 2학기 수강신청 안내

일정 제목
[ 수강신청 기간                    ]

시작일
[ 2026-08-03 ]

종료일
[ 2026-08-07 ]

메모
[ 장바구니 기간도 다시 확인          ]

[ 저장 ]
```

## 13. 1차 구현 범위 요약

```text
홈 화면
-> guestId 생성/확인
-> 학과 선택
-> 공지 목록 화면
-> 공지 상세 화면에서 본문 확인
-> 공지 저장 모달
-> 내 공지함 화면
-> 폴더 관리 모달
-> 내 일정 화면
-> 일정 등록/수정 모달
```

1차의 핵심은 `공지 조회`, `CAI Notice 내부 본문 확인`, `공지 저장`, `폴더 관리`, `ScheduleEvent 등록/조회`다. 로그인, AI, 알림, 공유, 협업, 관리자 기능은 2차 이후로 분리한다.
